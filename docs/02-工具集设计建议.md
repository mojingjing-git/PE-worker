# 极简 Agent 工具集设计建议

> 前提：目标环境是 **Win7 PE / XP PE**（32 位为主），**有网络**，并且**可以跑 ToDesk 这类远控工具**；同时要向后兼容 Win10 / Win11 PE。
> 基线功能：读取文件、写入文件、执行命令。本文回答「还能低成本加哪些 tool」。

---

## 0. 先看 ToDesk 这个前提带来的架构简化

ToDesk 能在 PE 里跑，意味着**桌面上有一个真人，而且随时能接管**。这一条直接砍掉一大堆复杂度：

| 原本要做的 | 有 ToDesk 之后 |
|---|---|
| agent 自己做 TUI / 终端交互 | ❌ 不需要，人在 ToDesk 里看着就行 |
| agent 做远程控制 / 文件传输通道 | ❌ 不需要，ToDesk 自带 |
| agent 做截屏回传 | ⚠️ 降级为可选（只在 ToDesk 掉线时才有意义） |
| agent 做「人机确认」交互 | ⚠️ 可以简化为「写个提示文件 + 等人改」或直接自动放行 |

**还额外送了两个好处：**
1. 出问题时人能立刻手工接管，所以 agent 可以设计得更"敢干"，不需要那么多兜底交互。
2. 人可以充当"最后一公里"的救火队（比如驱动没起来、网卡没配好），agent 不用处理这些边缘情况。

**驱动方式三选（可并存）：**
- **控制台交互式**：人在 ToDesk 窗口里敲，agent 调 LLM 并执行 —— 最简单，先做这个
- **内网轮询**：agent 定时向一台内网服务器拉任务 / 回传结果 —— 无人值守时用
- **手动触发**：人在 PE 里手动双击运行一次 —— 调试用

## 1. 关于网络：别自己写 TLS

> 🚫 **本节已按「选 Go 1.20」修订的部分**：选 Go 后**不需要打包 curl.exe、不需要 cacert.pem 文件**（Go 自带 `crypto/tls`）。
> ⚠️ **但有一条审核发现的修正**：Go 的 TLS **密码学部分**是白送的，**信任库不是** —— Windows 上 Go 的 `crypto/x509` 走 `systemVerify()` → **crypt32.dll 的 CryptoAPI，读系统根证书库**（已核实 Go 1.20 源码）。
> 所以必须**把 Mozilla CA bundle 用 `//go:embed` 嵌进 exe**，赋给 `tls.Config.RootCAs`，否则 WinPE 过时的根证书库会导致握手失败。详见 `PLAN.md` §0.5 A1。
> 本节下面的 curl / BearSSL 内容**只对 C/C++ 成立**，保留作历史参考。

有网 ≠ 能上 HTTPS。Win7 PE 的 SChannel 默认只开 TLS 1.0，XP 更是只有 TLS 1.0，**公网 API 基本连不上**，这是环境限制，改设置没用。

三个低成本出路（按推荐度）：

1. **直接 bundle 一个静态 curl.exe**（推荐）
   - `xpharness` 已验证：curl 7.42.1 + OpenSSL 1.0.2u 静态版，在 XP 上跑通 TLS 1.2
   - 成本几乎为 0：`download` / `upload` 两个工具直接调 curl 的命令行，**HTTP 和 HTTPS 一起解决**
   - 体积约 1~3MB，无运行库依赖（MinGW 静态编译）
   - 注意：OpenSSL 1.0.2 已 EOL，内网自用可接受
2. **静态链接 BearSSL / mbedTLS**，自己写极简 HTTP 客户端
   - BearSSL 只有几十 KB，支持 TLS 1.2，适合"极简"这个目标
   - 工作量中等，但完全自主可控
3. **不碰 TLS**：PE 里只发明文 HTTP 到一台内网中转机，由中转机去连 HTTPS
   - 最省事，前提是有可信内网

> ⚠️ 千万不要试图用 `WinHTTP` / `WinINet` 去连公网 HTTPS —— 在 Win7 PE 上会卡在 TLS 握手上，而且报错信息很含糊，排查成本极高。

## 2. 工具分层总览

| 层级 | 定位 | 数量 | 实现成本 |
|---|---|---|---|
| **Tier 1** | 顺手就有，只是已有能力的参数化 | 10 个左右 | 几乎为 0 |
| **Tier 2** | 低成本、高价值，PE 场景刚需 | 9 个左右 | 每个 20~100 行 |
| **Tier 3** | 可选，先不做 | 4 个 | 中等 |
| **Tier 0** | **不要自己实现**，交给 `exec` | — | 0 |

---

## 3. Tier 1 — 零成本扩展

这些本质上都是「read/write/exec 换几个参数」，实现成本几乎为零，但对 LLM 的可用性提升极大。

| 工具 | 难度 | 做什么 | 关键实现 |
|---|---|---|---|
| `ls` | ★ | 列目录，**带大小/时间/属性**，支持递归 | `FindFirstFileA` / `FindNextFileA` / `FindClose` |
| `stat` | ★ | 单个文件/目录的属性、大小、创建/修改时间 | `GetFileAttributesExA` + `GetFileSizeEx` |
| `mkdir` | ★ | 建目录（含多级父目录） | `CreateDirectoryA` 递归 |
| `rm` | ★ | 删文件/空目录 | `DeleteFileA` / `RemoveDirectoryA` |
| `mv` / `cp` | ★ | 移动/复制（含跨盘） | `MoveFileExA` / `CopyFileA` |
| `find` | ★ | 按通配符递归找文件（如 `*.wim`） | `FindFirstFileA` 递归 |
| `read` 增强 | ★ | 已有，加 `offset` / `limit` / `binary` / `encoding` 参数 | `SetFilePointerEx` — 读大日志必需 |
| `write` 增强 | ★ | 已有，加 `append` / `truncate` / `binary` 模式 | `CreateFileA` 的 `OPEN_ALWAYS` + `FILE_APPEND_DATA` |
| `base64` | ★ | 编/解码。**在文本通道里传二进制就靠它** | 自己实现，约 60 行 |
| `cwd` | ★ | 查看/切换工作目录（**有状态**，所有工具共享） | 进程内全局变量 |
| `env` | ★ | 读环境变量（单个或全部） | `GetEnvironmentVariableA` / `GetEnvironmentStringsA` |
| `selftest` | ★ | **自检**：返回 PE 版本、架构、当前用户、可用工具、配置摘要 | 多 API 聚合 —— 调试神器 |
| `sleep` | ★ | 等待 N 秒，避免轮询打爆对方 | `Sleep` |

> `selftest` 和 `cwd` 这两个看着不起眼，实际最容易被低估：前者是本项目在 PE 里的第一个排查手段，后者能省掉 LLM 反复拼绝对路径的 token。

## 4. Tier 2 — 低成本、高价值（PE 场景刚需）

这些才是真正的"增量价值"，每一个在 PE 维护场景里都常用，实现难度都不高。

| 工具 | 难度 | 为什么值得加 | 关键实现 / 注意事项 |
|---|---|---|---|
| `sysinfo` | ★ | 第一手环境信息：OS 版本、架构、内存、计算机名、当前用户、开机时长 | `RtlGetVersion`（**别用 `GetVersionEx`**）+ `GlobalMemoryStatusEx` + `GetNativeSystemInfo` |
| `diskinfo` | ★ | **PE 里最常用的信息**：有哪些盘、什么类型、卷标、剩余空间 | `GetLogicalDrives` + `GetDriveTypeA` + `GetVolumeInformationA` + `GetDiskFreeSpaceExA` |
| `netinfo` | ★★ | PE 里经常"网到底通没通"是首要问题：各网卡 IP/掩码/网关/DNS/MAC | `GetAdaptersInfo`（`iphlpapi.lib`），需解析 `IP_ADAPTER_INFO` 链表 |
| `ps` | ★ | 进程列表（PID / 名称 / 内存），用来确认 ToDesk 是否活着、谁卡住了 | `CreateToolhelp32Snapshot` + `Process32First/Next` + `GetProcessMemoryInfo` |
| `kill` | ★ | 结束进程（杀卡死的安装程序） | `OpenProcess` + `TerminateProcess` |
| `hash` | ★★ | 校验镜像/文件一致性，装系统前后比对。**PE 里没有可靠的 certutil** | 自己实现 MD5 / SHA1 / SHA256，各约 100~150 行，纯可移植代码 |
| `download` | ★★ | **PE 里最有价值的一个工具**：从内网/外网拉文件下来 | **直接调 bundle 的静态 curl**，顺带解决 HTTPS |
| `upload` | ★ | 把日志/截图/结果传回去 | 同上，一个工具的两面 |
| `log` | ★ | 上报一行状态 / 发个通知 | 复用 `download` 的传输层 |
| `reboot` | ★ | 装完就重启。PE 里必需，且要能强制 + 延迟 | `InitiateSystemShutdownExA`（PE 里没有正常的关机流程） |
| `open` | ★ | 在 PE 会话里启动一个 GUI 程序（比如拉起 ToDesk） | `CreateProcessA` + `WTSGetActiveConsoleSessionId` |

> **`diskinfo` + `netinfo` + `ps` 这三个是 PE 排查的"三件套"**，加起来不到 300 行，但能让 LLM 直接掌握机器状态，不用靠解析 `cmd` 输出。

## 5. Tier 3 — 可选，建议先不做

| 工具 | 难度 | 说明 |
|---|---|---|
| `reg` | ★★ | **读离线系统注册表**：`RegLoadKey` 挂载 `C:\Windows\System32\config\SOFTWARE` 后读，改完 `RegUnLoadKey`。这是"修不能开机的系统"的杀手锏，但属于进阶功能 |
| `win` | ★★★ | 枚举窗口 + `SendInput` 模拟点击，用于自动化装系统 GUI。**风险高、易失控**，除非有明确需求否则别做。但**枚举窗口**（只列标题/坐标，不注入）成本低，能大幅提升 `screenshot` 的精度 |
| ~~`screen`~~ | — | **已升级为 MVP 的 `screenshot`** —— 有了视觉模型之后从"可选"变"核心"，见 `docs/05` |
| `patch` | ★ | 按文件偏移改字节。用途窄，但实现只有几行 |
| `clipboard` | ★ | 读写剪贴板，交互模式下方便贴长文本 |

## 6. Tier 0 — 千万不要自己实现，交给 `exec`

这是本方案最大的省力点：**PE 镜像里本来就带了一大堆系统工具**，`exec` 一条命令就能用，不需要写任何代码。

| 需求 | 直接用 |
|---|---|
| 分区 / 格式化 | `diskpart /s script.txt` |
| 灌镜像 / 打驱动 | `dism` / `imagex` |
| 修复引导 | `bcdboot` / `bcdedit` |
| 文件系统检查 | `chkdsk` / `attrib` |
| 网络配置 / 诊断 | `netsh` / `ipconfig` / `ping` / `netstat` |
| 离线注册表 | `reg.exe load/unload/query/add` |
| PE 自身控制 | `wpeutil` / `net start` |

> 唯一要注意的是：**不同版本 PE 自带工具不完全一样**，Win7 PE 有 `imagex` 没 `dism` 的用法差异。所以 `exec` 的错误返回要如实透传 stderr，让 LLM 自己看到"命令不存在"并调整。

**建议再加一个 `run_script`**：把多行批处理写成临时文件再执行。
- 难度 ★，价值 ★★★★★
- 彻底避开 `exec` 的引号/转义地狱，LLM 写多行脚本时不用小心翼翼
- 也是用 diskpart / dism 的唯一优雅姿势

## 7. 让工具"便宜"的 6 条设计约定

这些约定本身不增加工作量，但决定了后面加工具是不是 5 分钟的事：

1. **所有工具统一返回单行 JSON** —— `{"ok":true,"data":{...}}` / `{"ok":false,"code":3,"msg":"..."}`
   - LLM 解析稳定，不用猜格式
   - 天然绕开 PE 的 codepage 乱码问题（内部统一 UTF-8）
2. **输出统一 UTF-8** —— PE 控制台默认 OEM 代码页，中文必乱。所有字符串在出工具前显式转换一次
3. **每个工具都带 `timeout`** —— `exec` 必须强制超时 + 杀进程树，否则一个交互式程序就把 agent 冻住
4. **`exec` 加白名单 + 审批开关** —— 默认只允许 PE 自带工具清单；危险命令（`diskpart clean`、`format`、`del /f /s`）单独确认。**PE 里误删分区是不可逆的**
5. **错误不抛异常，返回错误码** —— 单文件免 CRT 程序里异常处理很麻烦，用返回码最省事
6. **工具自描述** —— 内置一个 `help` / `tool_list`，把工具的 JSON Schema 直接吐出来给模型看；加新工具不用改提示词

## 8. XP / Win7 PE / Win10 PE 三档兼容的 API 红线

这几个坑不踩，一套代码就能同时跑在 XP PE 和 Win10 PE 上：

| 别用 | 改用 | 原因 |
|---|---|---|
| `GetTickCount64` | `GetTickCount` + 自己处理回绕 | **Vista+ 才有**，XP 上没有这个导出 |
| `RegGetValueA` | `RegQueryValueExA` | Vista+ 才有 |
| `GetVersionExA` | `ntdll!RtlGetVersion` | Win8.1+ 无 manifest 会返回假的版本号 |
| `SetThreadDescription`、`PathCchXxx`、新版 `Wlanapi` | 老 API 或自己实现 | 全是 Win8/10 才有的 |
| `W` 版 API 依赖 locale 资源 | 优先用 `A` 版 + 显式 `MultiByteToWideChar` 转换 | 精简 PE 常缺 locale 文件 |
| 64 位进程枚举 | 32 位进程用 `TH32CS_SNAPMODULE` 时只能看到 32 位模块 | 属正常限制，文档里说明即可 |

**CRT 策略**：`/NODEFAULTLIB` 完全免 CRT，或静态链接 CRT。**绝对不要依赖 VC++ 运行库** —— 这是 `xpharness` 踩过的坑（它的 curl 依赖 `msvcr80.dll`，结果在纯净 XP 上直接启动失败）。

**编译目标**：`_WIN32_WINNT=0x0501`（XP）打底，需要新 API 的地方用 `GetProcAddress` 动态取，取不到就降级 —— 这样一份二进制三档全兼容。

## 9. 推荐参考：Pi 的四工具最小核心

`earendil-works/pi`（MIT，约 6 万星，Mario Zechner 做的极简终端 coding agent）的核心哲学非常值得直接借用：

> **Agent = Model + Harness**
> 只内置 **4 个工具**：`read` / `write` / `edit` / `bash`
> 系统提示词严格控制在 **不到 1000 token**（对比 Claude Code 约 55000 token）
> 其余所有能力（子代理、计划模式、Web 搜索、MCP）全部靠扩展按需加

**它的 4 个工具几乎正好对应本项目的基础三件套**，只多了一个 `edit`：

| Pi 的工具 | tinker 的对应 |
|---|---|
| `read` | `read`（带 offset / limit） |
| `write` | `write`（带 append 模式） |
| `edit` | **← 本例新增，搜索替换式精确编辑** |
| `bash` | `exec` / `run_script` |

### 三条可以直接抄的设计

1. **加 `edit` 工具**（难度 ★）
   - 就是精确的「搜索 `old_text` → 替换为 `new_text`」，要求 `old_text` 唯一（否则报错让模型给更多上下文），改前存 `.bak`
   - 比让模型 `write` 整个文件省 token 得多，也更不容易写坏文件
   - 这是 Pi 四工具里唯一本项目原设计没有的，**建议补进 MVP**
2. **系统提示词要短**
   - 别在提示词里把 12 个工具的用法一个个写清楚 —— 改成内置一个 `help` 工具让模型自己查（见第 7 节第 6 条）
   - Pi 的做法是「工具名 + 一行描述」就够，细节靠工具返回的错误信息自我纠正
3. **留两种非交互模式**
   - `-p "指令"` 一次性执行（对应 Pi 的 print / JSON 模式）
   - RPC 模式：stdin/stdout 走 JSONL（对应 Pi 的 RPC 模式）—— 这也是将来想接「内网轮询」或别的宿主程序时最省事的接口

> ⚠️ **但 Pi 本身跑不了 Win7 PE**。它要求 Windows 11 + Node.js 22+，而 Node 自 v14 起就拒绝 Windows 7；更致命的是 Win7 控制台不支持 ANSI/VT（`ENABLE_VIRTUAL_TERMINAL_PROCESSING` 是 Windows 10 1511 才加的），Pi 的 TUI 在 Win7 上会渲染成乱码。
> **所以正确的做法不是"想办法跑 Pi"，而是"把 Pi 的最小内核用 Go 重写到能跑在 PE 里"** —— 这正好就是本项目在做的事。

## 10. 推荐的 MVP 工具集（14 个功能工具）

先做这 14 个，覆盖 PE 场景 90% 的需求：

```
1.  exec        —— 执行命令（超时 + 捕获 stdout/stderr + exit code）
2.  run_script  —— 多行批处理，写临时文件后执行
3.  read        —— 读文件（offset / limit / binary；图片扩展名 → 返回图片内容块）
4.  write       —— 写文件（append / truncate / binary）
5.  edit        —— 精确搜索替换编辑（存 .bak）  ← 对齐 Pi 的四工具核心
6.  ls          —— 列目录（含大小/时间/属性，可递归）
7.  find        —— 按通配符递归找文件
8.  sysinfo     —— 系统信息（版本/架构/内存/用户名/开机时长）
9.  diskinfo    —— 磁盘与卷（盘符/类型/卷标/剩余空间）
10. netinfo     —— 网络（IP/掩码/网关/DNS/MAC）
11. ps / kill   —— 进程列表与结束
12. download    —— 拉文件（Go 用 net/http；C 用 bundle curl）
13. hash        —— 文件校验（MD5/SHA256）
14. screenshot  —— 截屏给模型看（见 docs/05）
```

再加两个非功能性但很关键的：

```
15. selftest    —— 自检，PE 里的第一个排查手段
16. help        —— 吐出工具 JSON Schema，供模型自发现
```

**Tier 3 的先放一放**：`reg`（离线注册表）、`win`（窗口枚举）、`patch`、`clipboard` —— 等 MVP 跑通、确实遇到需求再加。接口按第 7 节的约定设计，加一个只要几十分钟。

> 注意：Tier 3 里的 `screen` **已经升级为 MVP 的 `screenshot`** —— 有了视觉模型之后它从"可选"变成"核心"。理由见 `docs/05-视觉与截图支持设计.md`。

## 11. 一句话总结

> 有了 ToDesk，agent 只需要做「**手和眼**」，不需要做「脸和腿」。
> 把力气全花在 **exec / run_script / 文件操作 / 三件套诊断信息 / download / hash** 上，
> 剩下所有系统级操作（分区、灌镜像、修引导）统统交给 PE 自带的命令行工具，
> 再用「统一 JSON 返回 + 统一 UTF-8 + 强制超时 + 命令白名单」四条约定兜底。
