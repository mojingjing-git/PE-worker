# 单机场景的传输与部署方案

> 前提修正：**默认用户只有一台机器**。上一轮提的「内网轮询」需要第二台机器跑 agent loop 和调 LLM，单机场景下它和「极简」直接冲突，**撤回**。
> 本文给出单机场景下的实际方案。
>
> ---
>
> ⚠️ **重要前提：本文的「打包 curl.exe」方案只对 C / C++ 成立。**
> 后来发现 `PE_SmartFixer` 用 **Go 1.20** 在 WinPE 里直接调 HTTPS 的 Qwen-VL API 并成功了 —— 因为 **Go 的 `crypto/tls` 是纯 Go 实现，静态链进 exe，完全不经过 SChannel**。
> 所以**如果语言选 Go，本文第 2 节整节作废**：不需要 curl.exe、不需要 cacert.pem，一个 exe 就够。
> 但 Go 的版本红线很陡：XP 需 Go ≤ 1.10，Win7 需 Go ≤ 1.20。**如果 XP PE 是硬需求，还是回到本文的 C + curl 方案。**

## 1. 单机场景没有第三条路：PE 侧必须自带 crypto

把条件摆出来，逻辑是死的：

| 事实 | 结论 |
|---|---|
| PE 机器自己跑不动 LLM（无 CRT、内存 64MB~2GB、模型好几个 GB） | LLM 只能在外部 |
| 所以必须走网络 → 公网 LLM API | API 一律要求 TLS 1.2+ |
| Win7 PE 的 SChannel 上限 TLS 1.0，且改设置无效 | **必须在 PE 侧自带 crypto** |

不存在"绕开"的余地。**所以问题不是"要不要自带"，而是"怎么带最省事"。**

---

## 2. 最省的做法：打包一个静态 curl.exe

**结论：把 TLS 的活儿整个外包给 curl.exe，你自己一行加密代码都不写。**

### 文件清单

```
X:\tinker\
├─ tinker.exe      ~100 KB    你的程序，无 CRT、无加密代码
├─ curl.exe        ~1.5 MB    静态编译 + 自带 OpenSSL，承担全部 TLS
├─ cacert.pem      ~200 KB    Mozilla 根证书包（curl 验证证书用）
└─ tinker.ini      几 KB      配置
                        ─────
                        约 2 MB
```

**2MB 对一个 U 盘或 PE 镜像来说完全可以忽略。** 对比一下：一套 PE 镜像本身通常 300MB~1GB。

### curl 的获取

参考 `xpharness` 已验证的路子：**curl 7.42.1 + OpenSSL 1.0.2u，静态编译**。
- 现成来源：[`OmegaAOL/curl-windows98`](https://github.com/OmegaAOL/curl-windows98)（专为老 Windows 打的静态包）
- 根证书：<https://curl.se/ca/cacert.pem>
- 必须是 **静态**编译版 —— 动态版会依赖 `msvcr80.dll` / `libssl-1_1.dll` 之类，在纯净 PE 上直接启动失败（这是 `xpharness` 踩过的坑）

### 调用方式

请求体由 tinker 自己写文件（避免超长命令行 + 转义地狱），然后：

```bat
curl.exe -s -S --max-time 120 --retry 2 --retry-delay 2 ^
  -K X:\tinker\curl.cfg ^
  -d @X:\tinker\req.json ^
  -o X:\tinker\resp.json ^
  https://api.deepseek.com/v1/chat/completions
```

`curl.cfg` 里放认证头（**关键：把 API Key 放在配置文件里，不要放在命令行上** —— 命令行参数在 PE 里用 `tasklist /v` 能看到）：

```
header = "Content-Type: application/json"
header = "Authorization: Bearer sk-xxxxxxxx"
cacert = "X:\\tinker\\cacert.pem"
```

> curl 7.42 不支持 `-H @file`，但支持 `-K configfile`（老版本就有），所以用 `-K` 这条路。
> 如果嫌 `cacert.pem` 麻烦想用 `-k` 跳过验证 —— **不要**，那等于把 TLS 的意义抹掉了。带 200KB 的文件值得。

**代码侧成本 ≈ 30 行**：`CreateProcess` 调 curl → 等它退出 → 读 `resp.json` → `MultiByteToWideChar(CP_UTF8, ...)` 转宽字符显示。就这些。

### 顺带把别的工具也解决了

同一个 curl 还能直接支撑：
- `download` / `upload` —— 从内网或公网拉文件、传日志，`-o` 直接落盘（**大文件不要走内存**）
- `log` —— 往一个 HTTP 端点 POST 一行状态

**一个 curl.exe 顶掉了三类工具的实现**，这是这个方案最划算的地方。

## 3. 配置文件长什么样

```ini
; X:\tinker\tinker.ini   —— 存成 UTF-8
[llm]
base    = https://api.deepseek.com/v1/chat/completions
model   = deepseek-chat
timeout = 120

; API Key 单独放，方便只改这一行
keyfile = X:\tinker\key.txt

[agent]
; 危险操作是否要人工确认：1=要，0=全自动
confirm = 1
; 命令白名单，逗号分隔；空 = 不放行任何 exec
whitelist = diskpart,dism,imagex,bcdboot,netsh,chkdsk,ipconfig,ping,reg,dir,copy,xcopy,attrib,format

[ui]
; 留空 = 用系统默认字体（推荐，PE 里别硬编码字体名）
font    =
fontsize= 12
```

中文文案也放这个文件（或单独的 `lang.ini`），按 UTF-8 读 —— 这样就绕开了第 5 节说的源码编码陷阱。

## 4. 那「轮询」什么时候才值得？

不是永远没用，而是**它的价值取决于机器数量**：

| 场景 | 该用哪个 | 原因 |
|---|---|---|
| **单台机器（你的默认场景）** | **直连 LLM API + 打包 curl** | 多一台机器就是纯负担 |
| 一次装几十台 / 集中运维 | 轮询 | 省掉每台分发 API Key，还能在服务端集中审批和留痕 |
| 机器在无外网的内网里 | 轮询 | 内网服务器当代理，PE 只连内网 |

**所以：先按单机直连做，把传输层抽象成一个小接口。等真有一批机器了，再在同一个接口后面加一个"轮询"实现 —— 界面和工具代码完全不用动。**

这也是为什么骨架里 `WorkerProc` 的循环结构值得写清楚：以后换驱动方式只改它。

## 5. 如果你坚持"只有一个文件"

有人会不爽于"多带一个 1.5MB 的 exe，而且还是 EOL 的 OpenSSL 1.0.2u"。那唯一的路是**把 TLS 静态链进 tinker.exe 自己**：

| 要做的事 | 真实成本 |
|---|---|
| 静态链接 **BearSSL**（约 50KB，支持 TLS 1.2）或 mbedTLS（约 300KB） | 集成 + 证书校验回调，约 300 行 |
| 手写 HTTP/1.1 客户端（请求组装 + 分块响应解析） | 约 300 行 |
| 极简 JSON 取值器（提取指定 key 的字符串值 + 处理 `\\n` `\\"` 转义） | 约 150 行 |
| 错误处理 / 超时 / 重试 | 约 200 行 |
| **合计** | **约 1000~1500 行 C** |

**什么时候值得做：**
- 要嵌进 `boot.wim` 且在意镜像体积
- 不想分发一个 EOL 的 OpenSSL
- 有一劳永逸的洁癖，愿意先付这 1500 行

**什么时候不值得：** 目标是"极简"和"快速能用"。**用 1.5MB 换掉 1500 行加密代码，这才是极简。**

> 建议路径：**先用 curl 版跑通全流程**，把 `send_request()` 做成一个函数。等真的在意体积或 OpenSSL 了，再把函数内部换成 BearSSL 实现 —— 上层工具代码一行不改。

## 6. 传输层的几个实现细节

| 细节 | 做法 |
|---|---|
| 判断成功 | 看 curl 的**退出码**（0 成功），不要只看文件在不在 |
| 响应读取 | 走 `-o` 落文件再读，**不要走管道** —— 管道要处理阻塞和长度限制，落文件免掉这两个问题 |
| 超时 | 用 curl 自己的 `--max-time`，双保险（外层还有 `RunCmdCapture` 的 timeout） |
| 大文件 | `download` 用 `-o` 直接落盘，绝不读进内存 |
| Key 保护 | 放 `-K` 配置文件，别放命令行 |
| 字符编码 | 响应是 UTF-8 → 读进来用 `MultiByteToWideChar(CP_UTF8, ...)`；**别用 CP_ACP** |
| 代理 | 如果是内网环境，`curl.cfg` 里加 `proxy = http://10.0.0.1:8080` |
| 调试 | 加 `-v` 会把握手过程打到 stderr，PE 里排查 TLS 问题就靠它 |
